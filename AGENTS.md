## Project Overview

A **photography portfolio website** for Sumit Ubale, a wedding photographer in Shrigonda, Maharashtra, India. The site is a static, single-page application (SPA) built with vanilla HTML/CSS/JS, using GSAP for cinematic animations and Sirv CDN for image delivery.

Target keywords for SEO:
- Wedding Photographer Shrigonda
- Wedding Photographer Ahilyanagar  
- Candid Wedding Photographer Maharashtra
- Pre Wedding Shoot Shrigonda

## Development Commands

Since this is a static site, there is no build process. Use these commands for local development:

```bash
# Serve locally with Python
python -m http.server 8000

# Or with Node.js
npx http-server -p 8000
```

Then open `http://localhost:8000`.

## Content Management (Sirv Sync)

Images and videos are served via **Sirv CDN** (`https://exdevx.sirv.com`), not stored locally. To update portfolio content:

1. Upload new images/videos to Sirv in the appropriate folders (`/Wedding`, `/PreWedding`, `/video`, etc.)
2. Run the sync script from the repo root:
   ```bash
   python Python/sync-sirv.py
   ```
   Requires `SIRV_CLIENT_ID` and `SIRV_CLIENT_SECRET` in a `.env` file.

The sync script (`Python/sync-sirv.py`) fetches file listings from Sirv API and regenerates `data/portfolio.json` with optimized CDN URLs.

## Tech Stack

- **HTML5** - Semantic markup with SEO meta tags, Open Graph, Twitter Cards, and JSON-LD structured data
- **CSS3** - Modular stylesheets (see `styles/` architecture below)
- **JavaScript (ES6+)** - Vanilla JS, no frameworks
- **GSAP 3** + **ScrollTrigger** - Cinematic animations and scroll-based reveals
- **Lenis** - Smooth scroll implementation
- **Sirv** - CDN for optimized image delivery with automatic WebP conversion

## Architecture

### Content Flow

```
Sirv CDN (source of truth)
    ↓
Python/sync-sirv.py (sync script)
    ↓
data/portfolio.json (generated data)
    ↓
scripts/content-loader.js (fetches JSON, populates DOM)
    ↓
Gallery + Lightbox (interactive display)
```

### JavaScript Module Architecture

All scripts in `scripts/` are loaded as modules in `index.html`. Key modules:

| File | Purpose |
|------|---------|
| `core.js` | **Central utilities**: Lightbox engine, VideoObserver (lazy load + auto-pause), VideoHover (play on hover), Media factory, DOM utilities |
| `content-loader.js` | Fetches `portfolio.json`, populates gallery grid and events section |
| `gallery.js` | Homepage gallery filtering and lightbox integration |
| `gallery-loader.js` | Gallery page (`pages/gallery.html`) specific loader |
| `album-loader.js` | Albums page (`pages/albums.html`) specific loader |
| `service-loader.js` | Service page (`pages/service.html`) dynamic content loader |
| `hero.js` | GSAP hero section animations |
| `sections.js` | GSAP scroll-triggered reveal animations |
| `navigation.js` | Mobile menu toggle |
| `smooth-scroll.js` | Lenis initialization |
| `whatsapp.js` | WhatsApp CTA with context-aware pre-filled messages |
| `loader.js` | Page loading lifecycle |
| `gsap-init.js` | GSAP configuration and defaults |

**Pattern**: Page-specific loaders call `Core.DOM.injectGlobalComponents()` to inject shared nav/footer.

### CSS Architecture

Styles are modular and loaded in `index.html`:

| File | Purpose |
|------|---------|
| `theme.css` | Design tokens (colors, typography variables) |
| `base.css` | Reset, typography, utility classes |
| `layout.css` | Grid systems, containers, responsive breakpoints |
| `components.css` | Sections, nav, hero, gallery, contact, footer |
| `animations.css` | GSAP animation classes, reduced-motion support |
| `loader.css` | Page loader styles |
| `lightbox-video.css` | Lightbox + custom video player controls |
| `service.css` | Service page specific styles |
| `project-card.css` | Card component styles |

### Data Files

- **`data/portfolio.json`** - Generated by Sirv sync. Contains `portfolio.images` (by category) and `recentEvents`
- **`data/services.json`** - Static service definitions (weddings, pre-wedding, cinematics) with copy and gallery data

## Key Implementation Patterns

### Image Handling

- Images are **always served from Sirv CDN**, never local
- Use `?w=800&q=80` query params for optimization
- Gallery items use `loading="lazy"` and opacity transitions for smooth loading
- Videos use `preload="none"` with IntersectionObserver for lazy loading and auto-pause when out of view

### Gallery System

- Homepage gallery: `content-loader.js` → `Core.Media.createItem()` → Lightbox
- Full gallery page: `gallery-loader.js` with category filtering
- Albums page: `album-loader.js` with dynamic album generation

### Video in Gallery

- Videos play on hover (desktop) or tap (mobile)
- Only one video plays at a time
- Lightbox opens with custom video controls (play/pause, progress, volume, speed, fullscreen)

### SEO Requirements

Every page must include:
- Unique `<title>` with location keywords
- Meta description with keywords
- Open Graph tags
- Twitter Card tags  
- JSON-LD structured data (`@type`: `LocalBusiness` + `Photographer`)
- Canonical URL
- Alt text for all images

### WhatsApp CTAs

All WhatsApp buttons must include a pre-filled message via `whatsapp.js`. Context-aware messages based on which service/page the user is viewing.

## Performance Constraints

- **No heavy frameworks** - Vanilla JS only
- **Minimize DOM operations** - Use `DocumentFragment`, batch updates
- **Images max 300KB** - Let Sirv handle optimization
- **Lazy load everything below fold**
- **Respect `prefers-reduced-motion`** - Check CSS and GSAP for reduced-motion fallbacks

## Accessibility Requirements

- Semantic HTML (`<header>`, `<main>`, `<section>`, `<footer>`)
- ARIA labels on interactive elements
- Keyboard navigation for lightbox (Escape, Arrow keys, Space)
- Focus indicators
- Alt text for images
- Color contrast WCAG AA compliant

## Codex Instructions

When modifying code:

1. **Preserve vanilla JS** - Do not add frameworks like React/Vue
2. **Maintain performance** - Avoid heavy libraries, minimize DOM operations
3. **Keep SEO intact** - Do not remove meta tags or structured data
4. **Respect animation system** - GSAP animations have specific timing/easing; test visual changes
5. **Image URLs** - Use Sirv CDN URLs with optimization params, never assume local paths
6. **Content updates** - Prefer Sirv sync over manual JSON edits; if manual, maintain the schema

When adding new features:
- Check if GSAP/ScrollTrigger are available (graceful degradation if not)
- Ensure mobile-responsive
- Test lightbox keyboard navigation
- Verify reduced-motion support
