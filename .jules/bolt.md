## 2026-06-15 - Optimized Sorting and Formatting for Large Datasets
**Learning:** The primary performance bottleneck in client-side sorting for 1,000+ items was $O(N \log N \cdot M)$ complexity caused by calling $O(M)$ methods like `Array.indexOf()` inside the comparator. Pre-calculating comparison metadata into a lookup object reduces this to $O(N \log N)$. Additionally, redundant string manipulations (split/map/join) during DOM rendering for 1,000+ items can be significantly reduced by caching formatted names in the initial data processing pass.
**Action:** Always pre-calculate comparison weights and cache high-frequency string manipulations in the initial data processing pass to ensure $O(1)$ lookup complexity during sorting and rendering operations. Use `textContent` instead of `innerHTML` for simple text nodes to further reduce DOM overhead.
